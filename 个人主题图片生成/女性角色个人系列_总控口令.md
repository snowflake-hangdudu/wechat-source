## 四、四种生成模式

| 模式 | 组合逻辑 | 数量规则 |
|---|---|---|
| 混搭模式（默认） | 在选定范围内自由组合，不要求统一场景或单一主题；兼顾搭配合理与视觉差异 | 使用指定数量；缺失先核对 |
| 系列发布模式 | 按本期主题组织开篇、变化与收尾，形成发布顺序 | 使用指定数量；缺失先核对 |
| 素材库模式 | 遍历选定范围内全部有效组合 | 默认全部；也可指定本次数量 |
| 指定组合模式 | 按我给出的组合表逐项规划 | 以组合表为准；数量冲突先核对 |

混搭模式中的“随意”表示自由搭配，不表示忽略人体、服装活动范围、场景用途或角色身份。可在日常、通勤、度假与原作造型之间变化；每张仍须有独立、合理的场景。未指定期主题时，可建议“自由混搭篇”，不强行加入故事线。

混搭模式默认分配方式为自由混搭：优先不重复、减少相邻近似组合，不强制每个选项使用次数完全相同。明确指定均衡覆盖时，再尽量平衡各维度使用次数。系列发布模式默认按主题搭配并兼顾均衡；素材库模式默认稳定顺序遍历。

## 五、范围、数量与去重

1. 每个维度支持单选、多选或全部；未指定的维度使用全部选项。选择一个维度不自动缩小其他维度。
2. 指定数量时，只在所选范围内安排该数量，不自动继续全部剩余组合。
3. 默认组合键：角色代码＋画风＋服装＋配色＋姿势。跨期去重依赖实际读取的历史记录。
4. 场景、光线、景别不作为默认组合乘数。允许变体时，另设变体编号并记录差异；变体不是重做版本。
5. W10 默认保留当前角色自己的经典服装及原色，配色字段写 CANON，不套用纲手服装到其他角色。只有明确要求原作换色时，才参与 C01–C09 组合。
6. 对非原作服装，配色只改变衣服与已有配件，不改变角色肤色、发色、眼睛或标志印记。
7. 数量超过有效可用组合时，报告差额，核对减少数量或允许变体；不自行重复补足。
8. 不适配的组合列明原因及调整建议，确认后跳过或调整，不擅自删除。
9. 先区分理论组合数、已识别不适配项、历史重复项和本次计划数；尚未完成兼容性检查时，不把理论数称为有效数。
10. 全部选项的理论数：W10 保留原色时 7,380；W10 也参与九组配色时 8,100。均为单角色、兼容性筛选之前的数量，不是默认任务配额。

## 六、角色、画风与服装要求

- 仅使用明确成年角色形象；保持具体五官、发型、发色、眼睛、标记及成熟气质，避免模板脸。
- 身材自然丰盈，肩宽、胸腰臀、骨盆、身高协调；成熟知性、含蓄性感、衣着得体，不刻意裸露或使用色情化构图。
- 表情不建独立库，随角色和主题自然呈现。配饰暂不单独扩展，保留必要身份配件或已确认服装配件。
- 动作关节、重心、手部、持物与支撑关系真实。姿势保留关键机位与动作，但需适应鞋跟、衣长、面料及地面。
- 服装锁定领口、袖型、层次、系带、长度与材质，防止围巾与蝴蝶结、连裤袜与长筒袜、长短围裙混用。
- 泳装内层与短裤主体不透明；轻透只用于明确的外罩层。
- 每张一种主画风，不拼接多个画风模块。自然手绘感、成熟美感、细腻情绪贯穿；水墨、线描、水彩、平涂和版画分别保留媒介逻辑，不统一水彩滤镜。
- 模板人物不自动成为当前角色；人物、媒介、衣服、颜色和动作参考分别限定用途。

## 七、逐张场景规则

每张都要写完整英文场景提示词，不能只填“模糊背景”。

1. 明确地点、少量环境线索、时间、光线和必要支撑物，符合主题、服装及动作。
2. 现代装使用适合的现代生活环境；泳装使用海滨、泳池等适合的环境；原作服装优先角色世界观。跨时代设定须在规划中标注。
3. 背景简化、适度模糊或概括，低对比，不抢人物；不用满幅精细建筑和装饰填空。
4. 光向、色温、透视、投影和人物接触关系一致，不能把人物贴在无关背景上。
5. 不模糊掉动作必需的凳面、地面、栏杆、窗框或道具，避免悬空。
6. 模糊服从画风：水彩用淡洗与软边，线描用稀疏轮廓，平涂和版画用简化色块与层次，不强制摄影散景。
7. 不自动复制对照图背景。混搭模式允许不同地点，但相邻图尽量不重复同一场景结构。

## 八、个人系列与发布规划

- 按“作品／角色 → 分期 → 图片顺序”组织。混搭模式也可以归入个人系列，不要求每期只有一种服装、画风或场景。
- 相邻图片尽量在画风、服装、配色、姿势、景别或机位中至少改变两项。
- 不把同一姿势的连续换色当成整期主要变化；重复服装时同步改变动作、构图或生活情境。
- 系列发布模式安排开篇主图、中段变化与收尾；混搭模式优先整体丰富度和相邻差异。
- 有选择范围限制时尊重限制，不为追求变化擅自添加模板。
- 读取已有记录后减少跨期重复；没有记录时只能报告“未检查历史重复”。

## 九、初始化、核对与生成流程

1. 检查资料可读性及版本，报告缺失和冲突。
2. 回显角色、模式、四维范围、数量、分配方法、每批数量及特殊约束。
3. 核对必要空白项；可先给建议，但不视为用户确认。
4. 输出按发布顺序排列的规划：图片 ID、顺序、主题、画风、服装、配色、姿势、景别与机位、场景、时间与光线、适配说明、目标文件名。
5. 大量组合使用完整规划文件与分段预览，报告总数和当前范围；不要声称少量预览就是完整规划。
6. 等待我明确确认方案并要求开始。初始化、讨论、局部认可、整理文件均不自动授权出图。
7. 确认后，每张展开独立完整英文提示词，包含身份、画风、服装、配色、姿势、场景和约束；不能仅把编号传给生成工具。中文用于说明，生成提示词仅英文；已有姿势文件只调用英文部分。
8. 默认每批 3 张，配置优先；每张单独调用生成，剩余不足一批时按实际数量。单幅独立画面，不交付拼图、裁切放大模板或多视图代替独立重绘。
9. 检查角色、媒介、服装结构、颜色、人体、动作和背景融合；合格保留，只重做明确不合格项。
10. 在确认范围内持续推进，不每批重复请求授权。遇工具限制或必要资料缺失时如实记录断点，不宣称后台自动完成。
11. 完成本次数量后停止；后续“继续”须根据已保存进度说明将接续的任务范围，避免自动扩展数量。

## 十、文件名与固定身份

### 图片 ID

每张分配不变的 ID，例如 TSUNADE-000001。角色代码在首次规划确定；序号从实际登记的最大号继续，不依靠猜测历史。调期、重排、改发布主题或重做时，原图片 ID 不变。更换画风、服装、配色或姿势形成新作品时另建图片 ID。

### 文件名格式

~~~text
角色_画风_服装_配色_姿势_固定编号_版本.png
~~~

示例：

~~~text
纲手_FE-016_W02_C05_P08_000001_v01.png
纲手_FD-029_W01_C06_P02_000002_v01.png
纲手_FE-015_W10_CANON_P01_000003_v01.png
~~~

- 文件名不包含系列名称、期号、发布顺序、主题或场景。它只描述图片资产本身，跨系列复用不改名。
- 固定编号至少六位，与图片 ID 的数字部分一致；它不是发布顺序。例如角色代码为 TSUNADE 时，000001 对应 TSUNADE-000001。
- 期号用 S01、S02，发布顺序至少三位；这些字段仅写入清单和发布规划。
- 角色名固定，文件名避免空格及 / \\ : * ? " < > | 等文件名禁用字符。
- 画风保留原编号，浮世绘统一 UKIYOE；服装 W01–W10、配色 C01–C09 或 CANON、姿势 P01–P09。
- 初版 v01；失败重做递增版本。新场景变体另建图片 ID 并记录来源，不能仅用版本号掩盖新的作品。
- 文件扩展名必须与实际格式一致，不只改后缀。
- 目标文件名是规划值；只有实际保存和重命名成功才可报告完成。若生成平台不能指定或重命名，记录原始文件链接与目标文件名映射，不谎称已改名。
- 不覆盖合格原图。指定采用版本，旧版本保留并标记状态。

~~~text
作品_角色/
  S01_自由混搭/
    图片/
    角色_S01_规划与提示词.md
    角色_S01_图片清单.csv
  S02_本期主题/
    图片/
~~~

图片原件建议集中存放在角色的“图片资产”目录；上述分期目录用于规划和发布清单，按需使用图片引用，避免为每次发布重复创建原件。按实际交付能力建立目录；不能建立时通过文件名和清单维持同等关系，不声称已创建本地文件夹。

## 十一、清单与进度管理

每个实际生成任务维护规划与提示词 MD、图片清单 CSV，字段至少包含：

~~~text
image_id,series,issue,order,title,character,style_id,wardrobe_id,color_id,pose_id,scene,camera,variant_of,version,status,adopted,planned_filename,actual_filename,actual_file_link,review_notes,published_at
~~~

- 完整英文提示词按 image_id 与版本写入 MD，并记录所用模板版本或快照日期，避免后续模板更新导致无法追溯。
- 状态：待生成、待检查、合格、需重做、已发布；合格不等于已发布。
- 生成状态与文件保存情况如实登记；未检查不标记合格，未收到发布信息不标记已发布。
- 重新排序或跨系列复用只调整发布清单，不更改图片文件名或固定 ID。同一图片可对应多个发布记录；每条记录分别保存系列、期号、顺序与发布时间。
- 每批更新完成、重做、待生成数量和下一批编号；把断点写入记录，新聊天先读取记录再续接。
- 本总控文件定义规则；具体任务清单在角色与数量确认后建立，不伪造已生成记录。

## 十三、模板外参考图与扩展

支持使用不在现有模板库内的角色、画风、服装、配色、姿势及场景参考。先实际读取，再明确每张图的用途与继承范围。可以只参考一张图的某个部分，不自动照搬其他元素。

### 参考配置

~~~text
新增参考图：
参考用途：角色身份 / 画风 / 服装 / 配色 / 姿势 / 场景
仅参考的部分：
不继承的部分：
~~~

- 未明确新图替代还是扩充原选择时，先核对，不自动扩大生成数量。
- 一张图可承担多种用途，但必须分别说明。角色参考优先锁定身份，不把示范人物移植到当前角色。

- 场景参考同样服从背景简化、模糊、低对比及人物融合规则，不自动保留精细背景。
- 无法读取、遮挡、裁切或背面细节不清时说明局限，不将猜测作为已确认结构。
- 默认仅供本次任务使用，不自动写入正式模板库，也不自动安装 Skill。
- 模板外参考不绕过“先规划、后确认生成”的流程。

## 十四、交付与新聊天核对清单

- 本总控为工作规则与入口，四份模块 MD 保留具体提示词，不把链接等同于文件内容。
- 新聊天最好同时提供本总控、四份模块、对应参考图以及当前角色身份图；续做时另提供规划和图片清单。
- 原个人规范无法读取时，说明缺失，核对是否允许仅按本总控及已读模块执行；不无故假设它已被读取或已废除。
- 开始生成前，确认角色、模式、范围、数量、分配方法、批量大小、参考用途和命名规则。
- 所有生成提示词仅英文，包含实际展开内容；规划与核对使用中文。
- 输出目标文件名与实际图片之间的对应关系；平台不支持改名时提供映射，不宣称生成工具已按目标文件名保存。
- 图片名只含角色、画风、服装、配色、姿势、固定编号、版本，不含系列期号或发布顺序。跨系列复用只增加发布记录。
- 本次若仅要求整理、更新、核对或计算，禁止直接开始出图。
