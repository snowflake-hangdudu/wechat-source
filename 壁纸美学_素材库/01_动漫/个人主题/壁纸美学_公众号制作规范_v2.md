# 壁纸美学｜公众号图文、封面与跨作品模板规范（V2）

> 更新：2026-10-29。给下一段会话或其他制作者使用。本文是**制作和验收规范**，不是单期设计提案。封面按本期用户提供的《火影女忍者江户绘卷》参考图抽象出结构；**禁止把参考图的具体背景当成所有作品的通用背景**。

## 1. 每期交付物

1. **微信公众号正文 HTML**：完整内嵌当期全部壁纸，保留原图纵横比例，两列排版，**单文件 < 10,000,000 字节**。上下期各输出一份。
2. **公众号封面 PNG**：独立文件，**1880 × 800 像素**；不要嵌进 HTML，以免增加体积。
3. **可直接发布的标题**：注明原作与角色；分篇明确标记上／下篇。标题可以不同于封面短文案。
4. 用户要求时更新本 MD；默认不另做 ZIP、设计方案 PDF、长篇说明。

文件建议命名：`{作品}_{角色}_{篇别}_{数量}_final.html`、`{作品}_{角色}_{篇别}_cover_1880x800.png`。修改原成品时先保留可回退的旧文件。

## 2. 最重要：只复用封面结构，不跨作品复用背景

**强制原则：版式是可迁移的，视觉背景必须重新设计。**

可跨作品复用的只有：画布宽高比、左文右图的构图比例、人物主次层级、统一的阅读顺序、文字与人脸的安全区、素材融合质量等抽象规则。

**不得跨作品直接套用**：樱花枝、神社、和风卷轴、浪纹、红日、具体地景、印花纹理、固定调色板、装饰构件、上一期完整背景或 AI 生成的同款合成图。尤其不能因为《火影忍者》本期采用“江户绘卷”，就把相同樱花／江户山峦／浮世绘浪纹应用到《海贼王》的人物封面。

背景要由**作品世界观 + 当期角色 + 真实素材画风 + 当期主题**四个因素共同决定，不是先选一张通用背景再把人物贴上去。

| IP／作品 | 可考虑的背景语汇（按当期实图取舍） | 不应机械套用 |
|---|---|---|
| 《火影忍者》 | 木叶村、火影岩、忍者卷轴、和纸、山峦、忍具、森林；本期用户**明确指定**江户绘卷版式，所以允许樱花和版画浪纹 | 不要所有火影角色都固定一张江户樱花背景 |
| 《海贼王》 | 航海图、航线、船帆、港口、海雾、海浪、阳光、角色相关岛屿和建筑 | **不复用火影的忍者村、神社、江户樱花卷轴或同一整幅浪纹背景** |
| 《鬼灭之刃》 | 大正时代建筑、灯影、和服织纹、竹林、紫藤、与人物有关的刀纹与场景 | 不把火影／海贼王背景原样换人贴入 |
| 《原神》 | 对应国家／地区风貌、元素纹理、建筑与场景色系 | 不用一张泛动漫背景套所有国家和角色 |
| 《BLEACH》 | 尸魂界、建筑廊道、墨线与灵子氛围、人物所属阵营的视觉语言 | 不简单复制前述作品的花枝海浪方案 |

即使属于**同一作品**，不同角色也不应完全同景：如《海贼王》的娜美优先航海图／导航意象，罗宾可围绕书籍／古迹／历史文本，女帝可围绕女儿岛或女王式建筑，白星可围绕海底珊瑚和鱼人岛。**角色的独有识别优先于 IP 的通用符号。**

同一人物的上下篇可以保留排版、字体、少量识别元素以形成系列感，但要根据上下篇素材区别主图、色彩和细节，避免直接复制整张背景。用户另给参考图时，按其**结构**继承，画面元素仍须重新判断。

## 3. 封面结构 V2：左侧标题＋右侧人物群像

当前结构参考：用户上传的 `火影女忍者江户绘卷(2).png`。

- 画布 **1880 × 800**，比例 **2.35:1**。
- **左侧约 30%—35%**：稳定、留白充分的标题区。大字不能超过画面安全边距；避免将正文完整长标题塞进封面。
- **右侧约 65%—70%**：三幅人物素材**自然叠合**。一幅**绝对主图**置于中前景，占约 60%—70% 的人物注意力；其余两幅不同姿态较小、靠两侧或后景。
- 同一角色专场：三幅应是**同一人物的不同画面**，不可误生其他角色。人物脸部、发色、特征印记必须可辨认。
- 不要三张同宽竖框、直线裁切、硬边拼贴、重复面孔的机械排列；背景和衣发的过渡要自然。
- 背景与装饰取自**本期 IP 和素材**。当前火影示例中的樱花／红日／浪纹是**本次视觉方案的内容**，不是跨 IP 的模板必选项。
- 推荐左侧文字层次：`壁纸美学`（小） → `{角色名}`（最大） → `{上篇/下篇/期次}`（大） → `{作品名} · {数量}张壁纸`（小） → `{人物相关短句}`（可选，通常 8—14 字）。
- 人脸不被文字覆盖；缩小到手机封面预览仍能一眼看出角色和标题。整图克制、成熟、有画报感，不要 3D、夸张发光、贴纸和无意义文字。
- 图片生成只能作为合成方式；**必须目视核对每个中文字、额头印记、手指、面部、三图融合和最终裁切**。AI 有错字或错人时重做，不直接交付。

### 需要给下一次生成模型的封面指令要点

> 只参考封面样例的版式结构（左 1/3 标题留白、右 2/3 三幅人物自然叠合、主图突出）；不要复制样例人物与背景。依据 `{作品}`、`{人物}`、`{当期图片风格}` 重新构思背景。主图为 `{主图文件}`，配图为 `{配图1}`、`{配图2}`；保留原角色脸、发色、识别特征。文字仅有 `{栏目名}`、`{角色名}`、`{篇别}`、`{作品及数量}`、`{短句}`。输出 1880×800 PNG，禁止贴纸、硬框、3D、错别字与多余角色。

## 4. 标题规则：人物先于画风

- 标题可采用：`壁纸美学｜《作品》角色（篇别）：{一个与原作人物有关的评价或悬念}｜{数量}张人物壁纸`。
- **卖点是人物**，不是“画风好看”“壁纸绝美”。剧情描述不能编造；不知道的事实先核实。
- 两期标题应能连读：上篇引出人物经历或矛盾，下篇落到变化或担当；避免换个形容词重复同一标题。
- **封面大字用短版**，不要在 1880×800 图上塞入完整公众号标题。

本期已采用：

- 上期：`壁纸美学｜《火影忍者》纲手（上）：她曾怕过鲜血，却最终选择再次救人｜15张人物壁纸`
- 下期：`壁纸美学｜《火影忍者》纲手（下）：她赌过无数次，最后把余生押给了木叶｜15张人物壁纸`

## 5. HTML 正文排版：微信双列结构锁定

1. 正文容器最大宽度约 **640px**；采用米白纸感、深色正文、克制强调色；重要样式用**行内 `style`**。
2. 按当期画风分组，图片编号连续 `01—N`；用户要求顺序则严格按输入顺序，不自作主张漏图、删除或重新排序。封面单独发布，不插进正文开头。
3. 图片保留原纵横比，使用 `height:auto`；禁止固定裁切、拉伸、为了整齐而改变图片内容。
4. 人物专场文案以角色及当期实际作品为主，语气克制；**不强制添加冗长的人物生平介绍**。用户明确要求“极简／删除人物介绍”时，不再插入人物简介，分组介绍只保留必要文字。已有成稿若只要求改封面，不擅自重写正文。
5. 互动区可按用户要求保留评分／图号／画风反馈；不写“长按保存”及过度营销语。免责声明不能代替素材授权。

### 必须复制的两列骨架

```html
<table role="presentation" width="100%" border="0" cellspacing="0" cellpadding="0"
  style="width:100%;border-collapse:collapse;table-layout:fixed;margin:0 0 15px;">
  <tbody><tr>
    <td width="48.5%" valign="top" style="width:48.5%;vertical-align:top;padding:0;">
      <img src="{{IMAGE_01_SRC}}"
        style="display:block;width:100%;max-width:100%;height:auto;margin:0;padding:0;border:0;vertical-align:top;">
      <!-- 简短编号与图注 -->
    </td>
    <td width="3%" style="width:3%;padding:0;font-size:0;line-height:0;">&#160;</td>
    <td width="48.5%" valign="top" style="width:48.5%;vertical-align:top;padding:0;">
      <img src="{{IMAGE_02_SRC}}"
        style="display:block;width:100%;max-width:100%;height:auto;margin:0;padding:0;border:0;vertical-align:top;">
      <!-- 简短编号与图注 -->
    </td>
  </tr></tbody>
</table>
```

**不要改成 CSS Grid 或 Flex；不要把三格各分 33.3%；不要漏掉 `td width` HTML 属性；不要给图片增加 `<img width="100%">` 属性。** 奇数末张仍用同样表格，右侧留空单元格。

### 文件体积与图片

- HTML **严格小于 10,000,000 字节**，建议压缩到约 9,700,000 字节以下留余量。
- 本地离线版将所有图片内嵌为 `data:image/jpeg;base64,...`，可直接双击浏览，图片保留像素尺寸优先、仅适量 JPEG 压缩。
- 微信后台有时**会过滤 Base64 图片**。本地可以显示不代表粘贴到公众号能加载；如果过滤，应上传图片到公众号素材库并替换图片地址／逐张插入。
- 发布前必须用微信公众号后台**手机预览**验证实际两列、图片数量、清晰度、图注与阅读顺序。

## 6. 发布前 QA 清单（每次都做）

- [ ] 标题的作品／角色／篇别／数量正确，没有虚构剧情。
- [ ] 封面 1880×800、文字正确、缩略图可读、脸部清楚、没有被遮挡。
- [ ] **封面背景符合当前 IP／人物，未跨作品复用其他封面背景。**
- [ ] 同一角色三张素材自然融合，主次鲜明，不是三个硬框拼图。
- [ ] 所有用户图片进入 HTML，数量及原始顺序正确；检查重复与近似重复。
- [ ] HTML 每个表格使用 `48.5% / 3% / 48.5%` 三单元格且同时有 HTML 宽度属性及行内 style。
- [ ] 无拉伸裁图；图片均有对应编号；奇数最后一行正常。
- [ ] HTML 文件字节数 < 10,000,000，浏览器离线预览图片可见。
- [ ] 微信公众号手机预览首／中／末三组为两列，图片加载成功。
- [ ] 最终交付链接可下载；封面 PNG 与正文 HTML 独立保存。
